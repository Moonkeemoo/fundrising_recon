# fundrising_recon — дизайн

> Прикладна база кейсів фандрайзингу України часів війни (2022→2026) для
> маркет-ресьорчу: **як найкраще запускати збір у 2026, що зараз перформить, а що ні.**
> Автозбір даних у дусі Recon: дисциплінована генерація — кожне число несе
> провенанс і рівень довіри, аналіз спирається на перевірене.

- **Дата:** 2026-06-07
- **Репо:** `git@github.com:Moonkeemoo/fundrising_recon.git`
- **Статус:** дизайн узгоджено, чекає рев'ю спеки → план

---

## 1. Мета і не-мета

**Мета.** Зібрати, типізувати й проаналізувати кейси фандрайзингу України з 2022 р.,
щоб отримати прикладні висновки для запуску зборів у 2026: які **цілі / стилі /
способи** історично заходять, як це змінювалось, що на підйомі зараз.

**Не-мета.**
- Не вичерпний реєстр «усіх» зборів (його не існує; чесна широта, не повнота).
- Не зброя, не таргетинг людей для шкоди.
- Не платіжний/донорський інструмент — лише дослідницька база + дашборд.

**Критерій успіху.** Дашборд дає відповідь на питання виду «*ціль = FPV-дрони,
2026 → який спосіб+стиль найкраще перформив і чи тренд росте*», спираючись на
кейси з позначеним рівнем довіри, з видимим `N` за кожним висновком.

## 2. Рішення зі скоупу (узгоджено)

| Питання | Рішення |
|---|---|
| Універс кейсів | **Максимально широко**: великі фонди + публічні збори + індивідуальні/мілблогерські банки + діаспора + корпоративні + цивільні напрями (медицина, тварини, відбудова, енергетика) |
| Що таке «перформить» | **4 осі**: обсяг, швидкість/темп, віральність/охоплення, повторюваність/утримання |
| Джерела даних | **Тільки автозбір** (скрейпінг + LLM-екстракція) |
| Архітектурний підхід | **A — дисциплінований типізований пайплайн** (Recon-стиль, провенанс + confidence, тири джерел) |
| Розкладка дашборда | **A — аналітичний кокпіт** (сайдбар-фільтри + сітка графіків) |

## 3. Архітектура

П'ять стадій. Кожне значуще число несе провенанс і confidence.

```
1. SEED/DISCOVER  список акторів і джерел → Discoverer-агент розширює тему/домен
2. COLLECT        колектори по типу джерела (httpx, резюмовані, ретрай 429/5xx):
                    • structured  — Monobank jar API (JSON), офіційні звіти
                      UNITED24 / Come Back Alive / Prytula, Opendatabot           [Tier-1]
                    • news        — Forbes UA, Suspilne, Економічна правда тощо    [Tier-2]
                    • social      — X / Telegram / Instagram (сигнали віральності) [Tier-3]
                  сирий кеш → data/raw/
3. EXTRACT        LLM → типізований Case строго за JSON-схемою; провенанс+цитата
                  обов'язкові на кожне число (інакше поле = null)
4. ANALYZE        4 осі успіху + нормалізація + тренди 2022→2026
5. VISUALIZE      статичний HTML-кокпіт (читає data/cases.json)
```

### Стек

- **Python 3.12** + **Claude Agent SDK** для EXTRACT/DISCOVER (підписка Claude Code,
  Opus, без ключа — патерн Recon); **критик-валідатор** кейсів — на прямому Anthropic
  API (Sonnet, `temperature=0`), щоб суддя ≠ генератор (анти-self-preference).
- **httpx** — колектори; окремий парсер під кожен тип джерела.
- **Сховище — SQLite** (zero-config, файл у репо, ідеально для аналітичної бази й шерингу).
  *Postgres — опція на майбутнє, якщо знадобиться граф/багатокористувацькість.*
- **Візуалізація** — статичний HTML + легка charting-бібліотека (ECharts/Chart.js),
  читає `data/cases.json` (патерн `recon.report`/`recon.ideas`).
- `ruff` (lint/format) + `pytest` (тести). Детерміновані валідатори інваріантів.

### Модулі (одна відповідальність на модуль)

```
fundrising_recon/
├── src/fundrec/
│   ├── seed.py        # сід акторів/джерел + Discoverer (тема → нові джерела)
│   ├── collect/       # колектори по типу: monobank.py, reports.py, news.py, social.py
│   ├── extract.py     # LLM-екстракція raw → Case (структурований вивід за схемою)
│   ├── critic.py      # критик-валідатор (окрема модель, temp=0) → verification_status
│   ├── validate.py    # детерміновані валідатори (провенанс/суми/дати/валюта)
│   ├── dedup.py       # дедуп + мердж кейсів між джерелами (tier-пріоритет)
│   ├── analyze.py     # 4 осі + нормалізація + тренди + крос-таби
│   ├── store.py       # SQLite доступ (actors / sources / cases)
│   ├── export.py      # дамп БД → data/cases.json для дашборда

├── tests/

```

## 4. Модель даних (контракт)

Три сутності: **Actor**, **Source**, **Case**.

### Case
```
ІДЕНТИЧНІСТЬ
  id, title, actor_id, url
  date_start, date_end | ongoing, year                 # для трендів 2022→2026

ТИПІЗАЦІЯ
  goal     ціль        # контр. словник, ієрархія category > subcategory:
                       #   military (FPV/дрони, авто, РЕБ, боєприпаси),
                       #   medical (тактмед, евакуація, шпиталі),
                       #   humanitarian (цивільні, переселенці, прихисток),
                       #   reconstruction, energy, animals, science/education,
                       #   info-defense, other
  style    стиль[]     # мульти-тег: емоційно-особистий, прозоро-датний,
                       #   терміновість/криза, гейміфікація (progress/челендж),
                       #   селеб-драйв, грасрутс-спільнота, мем/сатира
  method   спосіб[]    # мульти-тег: Monobank jar, банк, крипта, NFT/merch,
                       #   аукціон, марафон/телетон, стрім, челендж,
                       #   корп-метч, платформа (UNITED24/Patreon)

ОБСЯГ
  amount_uah, amount_usd (нормалізовано), goal_amount, currency_raw

4 ОСІ УСПІХУ (стадія ANALYZE)
  volume_score        # нормалізована сума (перцентиль у межах категорії цілі)
  speed               # time_to_goal_days, velocity = uah/активний_день
  virality_score      # композит соц-сигналів; null якщо даних мало (НЕ 0)
  repeatability       # на рівні Actor: campaigns_count, recurring, retention-proxy

ДИСЦИПЛІНА (на кожне значуще поле)
  provenance: { field → { source_url, confidence 0-1, tier 1/2/3, note } }
  confidence_overall
  verification_status # auto | cross-checked | verified | conflict
  extracted_at, extracted_by_model
```

### Actor
`id, name, type (foundation | individual | milblogger | corporate | diaspora | state),
founded, links[]` — кейси приєднуються сюди → **повторюваність/утримання** рахується природно.

### Source
`url, type (structured | news | social), tier (1 | 2 | 3), access, license, actor_id`
— реєстр джерел; інваріанти Recon: чесний `access` (реально перевірено), завжди `license`.

## 5. COLLECT + EXTRACT і боротьба з шумом

«Тільки автозбір» дає прикладну базу лише з дисципліною проти правдоподібного сміття.

**COLLECT.** Колектори по типу джерела, резюмовані (ретрай 429/5xx), сирий кеш у `data/raw/`:
- **Monobank jar** — публічний JSON банки (сума/ціль/прогрес) → найнадійніше число.
- **Офіційні звіти** (UNITED24 / CBA / Prytula / Opendatabot) — парсер сторінок/звітів.
- **Новини** — стрічки видань (контекст, дати, суми зі статей).
- **Соц** — X / Telegram / Instagram: сигнали віральності (згадки, репости, пік).

**EXTRACT.** LLM зі **структурованим виводом строго за схемою `Case`**. Жорстке правило:
модель **зобов'язана дати `source_url` + цитату-підставу на кожне число**, інакше поле = `null`
(не вгадуємо). Кожне поле отримує `confidence` за tier джерела.

**Чотири рубежі проти сміття:**
1. **Дедуп + мердж** (`dedup.py`) — той самий кейс із кількох джерел зливається; число з
   найвищого tier перемагає.
2. **Крос-чек** — є Tier-1 число → воно істина; лише новинні → нижчий confidence;
   конфлікт сум → `verification_status=conflict` (видно в дашборді).
3. **Детерміновані валідатори** (`validate.py`, без LLM) — провенанс присутній, суми в
   адекватних межах, дати 2022→2026, валюта нормалізована.
4. **Критик-агент** (`critic.py`, окрема модель, `temp=0`) — «чи цитоване джерело реально
   підтверджує це число й типізацію?» → виставляє `verification_status`.

**Наслідок.** База чесно широка (автозбір), але кожне число має походження й рівень довіри.
Аналіз 2026-го спирається на `verified` + `cross-checked`; «сире» доступне окремо, помічене як таке.

## 6. ANALYZE: 4 осі та тренди

**Осі рахуємо, порівнюючи подібне з подібним** (інакше військові мегазбори топлять усе):

- **volume** — `amount_usd` у лог-шкалі (збори — power-law) → перцентиль усередині
  категорії цілі і загалом.
- **speed** — `time_to_goal_days` (де ціль відома й досягнута) + `velocity = сума/активні_дні`,
  нормалізовано по категорії.
- **virality** — композит наявних соц-сигналів (згадки, пік, медіа-підхоплення);
  `null` якщо даних мало (не 0).
- **repeatability** — на рівні Actor: к-сть кампаній, регулярність, чи актор тримає обсяг.

**Без примусового єдиного скору.** 4 осі окремо (радар на кейс); опційно — зважений
композит з налаштовними вагами.

**Тренди 2022→2026:**
- Часові ряди по кварталах: обсяг / к-сть зборів / медіанна швидкість — з розрізом
  по цілі / стилю / способу.
- **«Що перформить ЗАРАЗ vs 2022»** — порівняння вікна 2025-26 проти ранніх років по
  кожному виміру: що росте, що згасає.
- **Крос-таби** (серце прикладного висновку): теплокарта *ціль × спосіб*; *стиль × віральність*.

**Чесна магнітуда.** Кожен висновок показує `N` і покриття даними — щоб не довіряти
тренду з 3 точок.

## 7. Візуалізація — аналітичний кокпіт (варіант A)

Статичний HTML, читає `data/cases.json`. Темна термінальна естетика (як Recon-кокпіт).

- **Сайдбар-фільтри:** ціль, стиль, спосіб, рік, `verification_status` (за замовчуванням
  показує `≥ cross-checked`; можна зняти й бачити «сире широке»).
- **KPI-рядок:** Σ зібрано, N зборів, медіанна швидкість (у поточному фільтрі).
- **Тренд 2022→2026** — часовий ряд (обсяг / к-сть / швидкість, перемикач).
- **Теплокарта ціль × спосіб** — перформанс.
- **Лідерборд кейсів** — топ за обраною віссю, з радаром 4 осей на кейс.
- Кожен віджет показує `N` (чесна магнітуда).

## 8. Інваріанти коректності (`docs/INVARIANTS.md`)

| # | Правило | Наслідок порушення |
|---|---|---|
| 1 | Кожне число має `source_url` + цитату; без них поле = `null` | Вигадані суми → хибний маркет-ресьорч |
| 2 | `confidence` і `tier` на кожне значуще поле | Неможливо відділити надійне від шуму |
| 3 | Реальний `access`/`status` джерела (перевірено колектором) | Висновки на «даних», яких нема |
| 4 | `license` джерела завжди заповнена | Юридичний ризик перепублікації |
| 5 | Осі рахуються лише де є дані; `virality=null`, не 0 | Фальшива точність, тренд із порожнечі |
| 6 | НЕ зброя / НЕ таргетинг людей для шкоди | Поза призначенням |

## 10. Відкриті питання (вирішити під час планування)

- Доступ до соц-сигналів (X/Telegram/Instagram) часто за API-ключем/обмеженнями —
  у P1 з'ясувати, що реально доступно безкоштовно; де ні — `virality=null` (чесно).
- Список tier-1 джерел зі стабільними машиночитними числами (Monobank jar API формат,
  чи є відкриті дані UNITED24) — рекон на старті P0.
- Курс UAH/USD для нормалізації обсягу за датою (історичні курси НБУ — відкриті).
